# Задача: настроить автозапуск Code через очередь файлов (23.11.2026)

Цель: чтобы владелец не вставлял промпты руками. Другой Claude (из чата claude.ai) кладёт файл-задание в Test_Ai\queue\inbox\, наблюдатель на этом ПК сам запускает Code командой `claude -p` и пишет результат в Test_Ai\queue\done\.

ПРАВИЛА
- Работать в C:\Users\Aotat\Desktop\Test_Ai. Игру и проект Unity (C:\Games\ChopChop) НЕ менять. Ключи и пароли не печатать.
- Владелец ЯВНО разрешил фоновый запуск с `--dangerously-skip-permissions`. Ограничения держим в самих файлах-заданиях и в наблюдателе (ниже).
- Отчёт мне на русском, простыми словами.

ШАГ 1. Проверить, что есть CLI
- Найти исполняемый файл `claude` (where claude / PATH / папка установки Claude Code). Записать версию. Если CLI нет и Code работает только внутри приложения, остановиться и написать «CLI нет», ничего не ставить без спроса.

ШАГ 2. Папки
Test_Ai\queue\inbox, running, done, failed, logs. В queue\README.md кратко описать схему.

ШАГ 3. Наблюдатель Test_Ai\scripts\queue\watcher.ps1 (PowerShell, без внешних модулей)
- Опрос inbox каждые 15 с. Берёт самый старый файл *.md (другие расширения игнорирует и пишет в лог).
- Один запуск за раз (lock-файл queue\watcher.lock; если процесс-владелец мёртв, lock снять).
- Файл переносит в running\, затем запускает из каталога Test_Ai:
  claude -p "Прочитай файл <полный путь к файлу в running> и выполни задание из него полностью. Все правила и ограничения в файле обязательны." --dangerously-skip-permissions
  Вывод целиком в logs\<имя>_<дата-время>.log. Тайм-аут 120 минут, после тайм-аута процесс завершить и задание считать failed.
- После завершения: файл в done\ (код выхода 0) или failed\ (иначе), рядом <имя>.result.json: {task, started, finished, exit_code, timed_out, log}.
- Каждые 30 с писать queue\watcher_heartbeat.json: {time, state: idle|running, current_task}.
- Ничего не делает вне Test_Ai, не читает файлы из других мест как задания.

ШАГ 4. Автозапуск
Задача Windows Task Scheduler «TestAi_QueueWatcher»: запуск при входе пользователя и перезапуск, если процесс не работает (проверка каждые 5 минут, без дублей благодаря lock-файлу). Окно скрыто. Права обычного пользователя. Запустить задачу сейчас.

ШАГ 5. Самопроверка
Положить в inbox файл ping_<дата>.md с заданием: «Создай Test_Ai\queue\done\ping_ok.txt, в нём дата-время и слова "связь есть"». Дождаться результата (до 5 минут), убедиться, что: файл создан, ping_*.md в done\, result.json есть, heartbeat идёт.

ЗАВЕРШЕНИЕ
Отчёт queue\SETUP_REPORT.md: версия CLI, пути, что создано, результат самопроверки, как остановить наблюдателя (команда отключения задачи), известные ограничения. Больше ничего не менять.
